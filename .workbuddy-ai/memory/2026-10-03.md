# 2026-10-03

## 修复 CI 红叉：npm audit 高危漏洞阻断部署

**现象**：push 后 GitHub Actions 两个 job（build-blog / lighthouse）在
`npm run audit:dependencies`（即 `npm audit --audit-level=high`）处报红，退出码 1，
部署中断。commit 本身是成功的，红叉只是 CI 状态检查失败。

**根因**：传递依赖链 `purgecss@8 → fast-glob → micromatch → braces`，
braces 存在 GHSA-vfj7-8cjw-p6xm（深层嵌套模式导致栈耗尽 DoS，CVSS 7.5）。
关键点：**braces 至今没有修复版本**，最新版 3.0.3 仍在漏洞范围 `<=3.0.3` 内，
所以升级/override 都救不了，只能从上游换掉整条链。

**处理**：
- purgecss 8.0.0（最新）仍依赖 fast-glob；7.0.2 改用 `glob@^11`，不经过 braces。
  故 `npm i -D purgecss@^7.0.2`（major 降级，但 build.js 的 API 用法完全兼容）。
- 验证：build 成功且 `styles.min.css` 字节数与降级前一致（14700），
  npm test / validate:site 通过，audit 归零（0 vulnerabilities）。
- 防复发：`.github/dependabot.yml` 的 npm 更新加了 ignore（purgecss 8.x），
  否则 Dependabot 每周会把 purgecss 升回 8.x、漏洞重现。

**经验**：
- 遇到"传递依赖漏洞"先判断上游有没有 patched 版本，再决定升级还是换依赖，
  不要盲目 `npm audit fix --force`。
- 本地 `npm ci` 会被沙箱批量删除保护拦截（删 node_modules/.bin 超 50 个文件阈值），
  验证 lockfile 一致性改用 `npm ci --dry-run`。
