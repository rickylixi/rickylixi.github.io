## 🔴 严重事故：.nojekyll 导致全站崩溃

### 根因
- `.nojekyll` 被错误添加到 **main 分支**（源文件分支）
- GitHub Pages 实际从 main 分支提供服务（非 gh-pages 分支）
- `.nojekyll` 告诉 GitHub Pages "不要 Jekyll 构建，直接提供源文件"
- 结果：所有页面显示原始 Liquid 模板源码（`{{ }}`、`{% %}`），网站完全不可用

### 修复
- **删除 `.nojekyll`** 从 main 分支 → GitHub Pages 恢复自动 Jekyll 构建
- commit: `9785cea`，已成功 push
- 网站已恢复：首页 `<!doctype html>`，教学页 Liquid 标签 0 个

### 教训
- `.nojekyll` 只能放在已构建的输出目录（如 `_site/`），绝不能放源文件分支
- 在 GitHub Pages 源分支加 `.nojekyll` = 停用 Jekyll 构建 = 裸奔源码

## TikZ 图不渲染修复

### 根因
- 博文 `_posts/2025-10-04-latex.md` 使用 `<script type="text/tikz">` + TikZJax (`tikzjax.com`) 客户端渲染
- `tikzjax.com` 在中国大陆访问不可靠，WASM 加载超时导致图无法渲染
- TikZJax WASM 崩溃有**连锁效应**：一个图出错会导致同页面所有图都空白

### 修复
- 用 `node-tikzjax` (npm) 在构建阶段预渲染 TikZ 图为 SVG 静态文件
- SVG 输出到 `assets/tikz/tikzcd-commutative.svg` (交换图) 和 `assets/tikz/tikz-star.svg` (五角星)
- 博文改用 `<img>` 标签引用预渲染的 SVG
- 同时保留 LaTeX 源码在 ` ```tex ` 代码块中供读者参考
- 移除两篇博文多余的 `tikz: true` frontmatter
- 渲染脚本：`scripts/render-tikz.js`（需要 `npm install` 后本地运行）
