## 🔴 严重事故：.nojekyll 导致全站崩溃

### 根因
- `.nojekyll` 被错误添加到 **main 分支**（源文件分支）
- GitHub Pages 实际从 main 分支提供服务（非 gh-pages 分支）
- `.nojekyll` 告诉 GitHub Pages "不要 Jekyll 构建，直接提供源文件"
- 结果：所有页面显示原始 Liquid 模板源码（`{{ }}`、`{% %}`），网站完全不可用

### 修复
- **删除 `.nojekyll`** 从 main 分支 → GitHub Pages 恢复自动 Jekyll 构建
- commit: `9785cea`，已成功 push
- 网站已恢复：首页 `<!doctype html>`，教学页 Liquid 标签 0 个

### 教训
- `.nojekyll` 只能放在已构建的输出目录（如 `_site/`），绝不能放源文件分支
- 在 GitHub Pages 源分支加 `.nojekyll` = 停用 Jekyll 构建 = 裸奔源码

## build.js EISDIR 崩溃修复

### 根因
- `node-tikzjax` 的传递依赖里有两个包名带 `.js` 的目录：`node_modules/decimal.js/` 和 `node_modules/glob-to-regex.js/`
- `build.js` 的 PurgeCSS 内容收集用 `fs.readdirSync(dir, { recursive: true })`，在 Node.js 18+ 中会返回目录名
- `.filter(f => f.endsWith('.js'))` 把这些**目录**也加进了 PurgeCSS content 列表
- PurgeCSS 对目录执行 `readFileSync` → `EISDIR: illegal operation on a directory, read`
- 这是 build.js 预存的脆弱代码，任何引入的依赖包名带 `.js` 都会触发

### 修复
- `.filter(f => ...)` → `.filter(f => ... && fs.statSync(f).isFile())`
- commit: `01bb8b2`，已 push

- 从 `tikzjax.com/v1/` 下载 tikzjax.js、fonts.css
